# Детка Плюс

Публичный сайт центра коррекции и развития детей «Детка Плюс» в Липецке и компактная административная панель для управления контентом.

**Статус:** этап 1 реализован как демонстрационный черновик. Админка и визитки относятся ко второму этапу. Ниже после команд сохранены продуктовые требования.


## Запуск реализованного этапа 1

Нужны Node.js 24+ и Yarn 1. Команды выполняются из корня репозитория.

```sh
yarn install --frozen-lockfile
yarn db:seed
yarn dev:backend
```

В другом терминале: `yarn dev`. Сайт: http://localhost:3000, API: http://127.0.0.1:3001.
`db:seed` выполняет миграцию и добавляет только отсутствующие демонстрационные записи.
Отдельно применить миграции: `yarn db:migrate`. Существующий контент seed не перезаписывает.

Проверки и статическая сборка:

```sh
yarn generate
yarn typecheck
yarn build:backend
yarn test
```

Готовый статический сайт: `web/.output/public`. Backend: `yarn start:backend`.
Для проверки готового сайта при работающем backend: `yarn preview` (порт 3000).
Сервер возвращает настоящий HTTP 404 с готовым HTML, без SPA fallback.
Для просмотра новой сборки без переключения сохранённого релиза: `STATIC_ROOT=web/.output/public yarn preview`.
Запускаемые вручную серверы останавливаются Ctrl+C.

Настройки передаются через окружение; варианты перечислены в `.env.example`.
Для загрузки файла окружения можно использовать `node --env-file=.env dist/backend/main.js`.
Не переносите реальные заявки в демонстрационную базу.

## Что уже работает

13 статических страниц: главная, о центре, каталог и две демонстрации услуг,
список и демонстрация специалиста, галерея, раздел родителям и две статьи,
контакты, проект условий обработки данных. Все маршруты содержат основной текст
без JavaScript. У каждой страницы свои title, description, canonical, Open Graph
и JSON-LD. Sitemap и robots генерируются из того же содержимого.

В README не было подтверждённого списка услуг. Поэтому названия демонстрационных
услуг не являются утверждением об оказываемых центром услугах. Сотрудники, дипломы,
отзывы, фотографии детей, цены и телефон не выдумывались. Для визуального черновика созданы подписанные ИИ-фотообразы занятия и кабинета;
они не изображают реальных сотрудников, посетителей и помещения. Реальных фото и видео пока нет.
Статьи помечены как редакционные черновики для проверки директором.

Форма отправляет `POST /api/callbacks`: имя, телефон, комментарий, согласие.
Сервер проверяет поля, honeypot и Origin; ограничивает отправку пятью заявками
за 15 минут на IP. Состояние лимита сохраняется в SQLite. Reverse proxy должен
отсекать прямой внешний доступ к backend. Сейчас `trustProxy=false`:
при размещении за proxy нельзя бездумно доверять входящему X-Forwarded-For;
для реального запуска настройте доверие только своему proxy и внешний rate limit.
Локальный preview проксирует заявки с одного IP.

Заявка коммитится до уведомления. Email исключительно mock: попытка и результат
фиксируются в БД и логах без имени, телефона и комментария.
`MOCK_EMAIL_FAIL=1` позволяет проверить отказ уведомления. Подключение SMTP
остаётся отдельной задачей второго этапа. Реального SMTP в проекте нет.

## Устройство и публикация

- `web/`: Nuxt 4 SSG, Vue Options API, Less и Tailwind 4 через Vite.
  Компоненты разделены на index.vue, script.ts, style.less.
- `backend/`: NestJS 11 + Fastify, SQLite через встроенный node:sqlite, SQL-миграция.
- `shared/content.ts`: форма публичного снимка; `shared/demo.ts`: воспроизводимый seed.
- `shared/models.ts`: модели сотрудников, услуг, статей, медиа с проверкой разрешения,
  прайса, настроек, заявок и двусторонних шаблонов визиток.
- `admin/`: граница будущей CSR-админки. Element Plus установлен, но не попадает
  в публичный bundle; авторизации и редакторов на этом этапе нет.
- `content` в SQLite хранит документы по типу и slug, JSON payload, visible,
  sort_order и updated_at. Неопубликованные записи не попадают в снимок.
  Пока редактор отсутствует; публичный рендер использует контракт Page.
  Будущий редактор должен сохранять соответствующий публичный документ,
  а медиа пропускать через проверку разрешений до включения в него.

`yarn generate` снимает данные из SQLite и строит сайт для проверки.
Само редактирование БД **не обновляет** опубликованные страницы.

`yarn content:publish` создаёт запись building, фиксирует снимок, генерирует
отдельный каталог `storage/releases/<id>/public` и только после успешной сборки
атомарно меняет симлинк `storage/current`. При ошибке остаётся предыдущая версия,
а в publications записывается failed и причина. Одновременные запуски блокируются
файлом publish.lock. После аварийного завершения нужно проверить, что процесса
публикации нет, и удалить lock вручную; незавершённая запись building остаётся
видимой в журнале. `yarn publication:status` показывает последнюю попытку и
отличается ли текущий контент от опубликованного снимка.
Preview читает current при каждом запросе, поэтому видит смену без перезапуска.

Это локальная сборка и переключение, не внешняя публикация.
При размещении настройте сервер на каталог current, HTTP API на backend,
не используйте переадресацию всех неизвестных URL на главную.
Старые releases сохраняются для ручного отката; автоматической очистки нет.

По умолчанию `SITE_URL=http://localhost:3000`, `SITE_INDEXABLE=false`:
демонстрационный сайт содержит noindex и robots Disallow.
После утверждения материалов задайте реальный HTTPS origin в SITE_URL,
SITE_INDEXABLE=true и пересоберите. Домен detka-plus.ru не считается зарегистрированным.
Локальные canonical не должны попасть на рабочий домен.

## Браузерная проверка

Используется уже установленный Playwright Chromium, без установки в проект:

```sh
PLAYWRIGHT_MODULE=/путь/к/playwright CHROMIUM_PATH=/путь/к/chrome node tests/browser.cjs
```

Порты 3000 и 3001 должны быть свободны. Проверка поднимает собственные серверы,
использует временную SQLite, проходит 13 маршрутов на 1440 и 390 px,
проверяет меню, форму, загрузку изображений, отсутствие горизонтальной прокрутки и ошибок JS,
HTML без JavaScript и HTTP 404. Скриншоты: test-results/home-1440.png и home-390.png.
Браузер и серверы закрываются в finally. Проверяется новая сборка `web/.output/public`,
даже если существует `storage/current` со старым релизом. Внешняя карта Яндекса зависит от сети.

прайс и фиксированные двусторонние шаблоны визиток с PDF для печати.


## Задача

Создать современный, взрослый по визуальному языку, тёплый и понятный родителям сайт центра, работающего в том числе с детьми с особенностями развития. Сайт должен объяснять, как центр помогает семьям, знакомить со специалистами, показывать реальные условия занятий и давать возможность оставить заявку на обратный звонок. Второй результат — единый фирменный стиль для сайта и полиграфии.

Не ориентироваться на оформление bogdanya.ru: этот ресурс используется **только как пример состава разделов и направлений**, не как дизайн-референс.

## Технологии и принципы

- **Frontend:** Nuxt 4, Vue 3, TypeScript, Less, Tailwind CSS. Element Plus использовать избирательно, преимущественно в админке.
- **Рендеринг:** SEO-first. Страницы, индексируемые поисковиками, должны иметь содержательный HTML при первом ответе сервера/в SSG-артефакте, без зависимости от выполнения JS и подключения WebSocket. SSG — предпочтение для стабильного контента; SSR допустим там, где он объективно нужен.
- **Админка:** клиентский интерфейс, не индексируется. Не должна ломать статическую генерацию публичного сайта.
- **Backend:** небольшой единый backend; NestJS с Fastify adapter рассматривается как базовый вариант, но не вводить слои и инфраструктуру без конкретной потребности.
- **Данные:** SQLite для первой версии (с миграциями). Управляемый контент публикуется на сайт через контролируемую пересборку SSG или иное явно реализованное SEO-безопасное решение; сохранение в БД само по себе не должно ошибочно считаться публикацией.
- **Транспорт:** WebSocket RPC для интерактивных операций, HTTP для загрузки файлов и для необходимых SEO/служебных сценариев. Не заставлять поисковики получать контент через WebSocket.
- **Почта:** пока **фейковая отправка** уведомлений о заявках. Никаких реальных отправок SMTP без отдельного решения. В перспективе — SMTP почтового провайдера, а не собственный SMTP на VPS.
- **Стиль кода:** простота, читаемость, минимум зависимостей. Не переносить `/home/lisov/projects/ref` целиком; допускается изучать его как справочник удачных решений.

## Публичные разделы v1

1. **Главная:** позиционирование, проблемы и потребности родителей, направления помощи, специалисты, атмосфера центра, призыв оставить заявку.
2. **О центре:** подход, история и приветствие директора (когда предоставит), помещение, фотографии.
3. **Услуги:** список и отдельные SEO-страницы направлений; только реально подтверждённые направления.
4. **Специалисты:** фото, ФИО, специализация, квалификация и описание.
5. **Галерея:** фото/видео центра и занятий; материалы с детьми публикуются лишь при подтверждённых необходимых согласиях.
6. **Родителям:** полезные статьи и ответы на вопросы.
7. **Контакты:** адрес, карта Яндекса, реквизиты связи, фотография входа и инструкция «как найти».
8. **Цены:** необязательный раздел, включаемый через админку. Не придумывать цены; дождаться решения директора.

**Основное действие:** оставить имя, телефон и необязательный комментарий для обратного звонка. Также посетитель может самостоятельно приехать по указанному адресу. **Никаких** онлайн-календарей, бронирований слотов, личных кабинетов родителей или SaaS/CRM-системы.

## Административная панель v1

- Защищённый вход администратора.
- Редактирование информации о центре, контактных данных, базовых страниц и SEO-полей.
- Сотрудники: ФИО, должность/специализация, фото, квалификация, описание, публикация и порядок вывода.
- Услуги: содержание, изображение, связи со специалистами, публикация и порядок вывода.
- Медиатека: фото/видео, подписи и статус разрешения на публикацию материалов с детьми. Статус не заменяет само согласие.
- Статьи и раздел «Родителям».
- Прайс-лист: редактирование примерных цен и полное отключение публичного показа.
- Заявки на обратный звонок: сохранение, просмотр, статус обработки, лог имитации email.
- **Конструктор визиток:** фирменные фиксированные шаблоны; выбор сотрудника или ручной ввод имени, специализации, телефона и прочих нужных полей; двухсторонний предпросмотр, PDF для печати. Стартовый предполагаемый формат 90 × 50 мм — подтвердить перед выпуском в типографию; предусмотреть параметры вылетов и безопасных полей.

Не делать универсальный визуальный редактор, CRM, сложную ролевую модель, календарь или онлайн-оплату.

## Фирменный стиль

**Логотип «Детка Плюс» уже утверждён. Не редизайнить и не генерировать заново.** Использовать предоставленный обновлённый вариант в исходном качестве; если его нет в репозитории, запросить файл/временно явно обозначить место для него, но не создавать похожий логотип.

Опорные цвета:

| Назначение | Цвет |
|---|---|
| Тёплая кремово-жёлтая основа | `#FFF4D6` |
| Нежный сиреневый | `#C9B7E8` |
| Мягкий светло-зелёный | `#BFE5CF` |
| Акцентный малиновый из айдентики | `#D40B7C` |

**Обязательны** мягкие крупные градиенты и качественные деликатные растительные орнаменты (SVG/CSS/высококачественная графика). Они не должны мешать чтению. Важны спокойные отступы, хорошая типографика, доступность, контраст и адаптивность. Не тиражировать радугу отдельно от зарегистрированного логотипа.

Тон текста — уважительный, профессиональный, человечный: **помощь особенным детям и поддержка родителей**, без сюсюканья, стигматизации, выдуманной экспертизы и обещаний гарантированного результата.

## Критерии готовности первого черновика

- Можно запустить проект локально по задокументированным командам.
- Все публичные разделы имеют рабочие маршруты и адаптивный законченный вид, а не пустые заглушки.
- Индексируемые страницы возвращают содержательный HTML, метатеги, canonical, корректную семантику; предусмотрены sitemap/robots и реальные 404.
- Форма обратного звонка сохраняет заявку, показывает корректный результат и имитирует email без отправки наружу.
- На втором этапе: админка позволяет реально изменить данные, загрузить медиа, управлять публикацией и сформировать PDF визитки.
- Протестированы базовые пользовательские сценарии, сборка, типизация, доступность основных элементов и мобильные экраны.
